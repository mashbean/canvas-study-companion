# The repeatable weekly workflow

1. **Verify the week.** Check the current timetable, teaching week, groups, cancellations and course IDs. Never copy old dates as current facts. Email/calendar supplementation is optional and must be enabled by the student.
2. **Discover and select.** Read current modules with the independent API, choose the relevant module IDs and known pages/assignments/files, and save a verified local week plan. The bundled scripts are a starting point, not a substitute for source judgement.
3. **Collect evidence.** Fetch pages, modules, assignments, relevant announcements and attachments. Follow pagination and links. Record authentication errors, disabled indexes, hidden files and unavailable endpoints separately from empty lists.
4. **Fill external gaps.** Check library reading lists, electronic books, original PDFs and external tools through authorized routes. Keep Further/Extended references even where their full texts are unavailable. Do not bypass access restrictions.
5. **Review sources.** Separate required/recommended/preparation/background; original text/translation/assistant explanation; formal deadlines/suggested reading times. `lock_at` is not a deadline extension. Booking-tool `unsubmitted` is not proof of a missing assignment. An empty Canvas assignment list is not proof that the course has no assessment.
6. **Prepare the pack.** Use source-based paragraph IDs, preserve page/footnote/figure/formula boundaries, label summaries and gaps, and use the student's language. Retain unaffected translations and personal progress.
7. **Make it achievable.** Prioritize hard deadlines and the next class. Estimate reading and preparation separately. Include concepts, questions, an objection, a speaking exercise and useful expressions. A short preparation route is not a claim of complete reading.
8. **Validate and report.** Check links, original file signatures/hashes, source/version metadata, translation coverage, visual layout, highlights and progress. Report API, external access, translations and UI checks independently. Never call a mock test a live authentication test.

A practical rhythm is a full preparation pass near the end of the preceding week and a short change check before the first class. These are suggested manual checkpoints; this repository installs no automation. If the student explicitly requests scheduling, use their environment's supported scheduler and report its actual status and runtime requirements.

Every update should say what changed, what is still missing, and what is urgent. New metadata in a more complete API capture is not automatically a new publication. Do not overwrite original files or silently delete a reading merely because one request did not return it.

At week's end ask what helped, how long preparation took, and where translation was still needed. Change only one learning method for the following week.
